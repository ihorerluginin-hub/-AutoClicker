# Автокликер

Android-автокликер на `AccessibilityService`. Три кнопки, две шкалы, ничего лишнего.

Интерфейс намеренно урезан: без списка настроек, пресетов и плавающих панелей
с настройками. Всё, что нужно, — на одном экране.

```
[Статус]
[Служба включена / выключена — включи в настройках]

[        СТАРТ        ]   жми — клик по точке или повтор записи
                        долгое нажатие — принудительно клик по точке
[ ЗАПИСАТЬ КООРДИНАТУ ]   тыкнешь по экрану, точка запомнится
[   ЗАПИСАТЬ ЭКРАН   ]   записывает нажатия, потом СТАРТ их повторяет

Точка: 540, 1200
Скорость: 1.0×            шкала 0.5× … 5.0×
Итераций: без ограничения 0 = бесконечно, дальше до 10 000

Записано нажатий: 3
[ Очистить запись ]
```

Плюс всплывающая кнопка над другими приложениями: тап — стоп, долгий тап —
настройки. Появляется при запуске кликера, чтобы остановить его не возвращаясь
в приложение.

## Требования

- Android 8.0 (API 26) и выше
- Разрешение на специальные возможности — обязательно, без него не отправляются
  касания
- Разрешение на оверлей — только для всплывающей кнопки

## Сборка

```powershell
# local.properties: путь к SDK, LF-переносы строк обязательны
sdk.dir=C\:\\Users\\<user>\\AppData\\Local\\Android\\Sdk

gradlew.bat assembleRelease
```

APK: `app/build/outputs/apk/release/app-release.apk`

Подпись берётся из `local.properties`:

```
KEYSTORE_PASS=<пароль>
ALIAS_NAME=<алиас>
ALIAS_PASS=<пароль>
```

Сам `release.keystore` в репозиторий не коммитится.

## Что внутри

| Файл | Зачем |
|---|---|
| `service/ClickerAccessibilityService.kt` | Ядро: клик в точку, запись, воспроизведение |
| `service/OverlayController.kt` | Всплывающая кнопка |
| `service/Macro.kt` | Модель записи: штрихи и точки |
| `service/ClickerState.kt` | Состояние для UI без прямой связи со службой |
| `service/KeepAliveService.kt` | Фоновый сервис, чтобы системa не выпилила процесс |
| `data/ClickerConfig.kt` | Настройки: точка, скорость, итерации |
| `ui/MainActivity.kt` | Экран и режим выбора точки |

## Как это устроено

**Клик.** Клики идут по таймеру через `dispatchGesture`: жесты короткие и
независимые, при отказе системы просто пробуем снова через интервал.

**Запись.** Пишутся нажатия, а не движения. Берёмся за `onAccessibilityEvent`
с типом `TYPE_VIEW_CLICKED` — эти события система доставляет всегда.

Наблюдать за сырыми касаниями (`onMotionEvent` через touch exploration или
`TouchInteractionController`) не вышло: на TECNO KL8 с MediaTek Android 14 оба
возвращают ноль событий, хотя и флаг, и capability применяются. `dispatchGesture`
при этом работает штатно — расходится только направление «считать», но не
«слать».

**Воспроизведение.** Каждый штрих превращается в `Path` и уходит одним
`GestureDescription`, длительность делится на скорость. Штрихи идут цепочкой:
следующий ждёт колбэка предыдущего, иначе система начинает отклонять запросы.

## Ограничения

- Движения и протяжки не записываются, только нажатия
- Координата берётся из центра рамки элемента, а не из точки касания пальцем.
  Для кнопок одно и то же, для произвольных мест может попасть на край
- На Android ниже 13 всплывающая кнопка и наблюдение за движениями недоступны,
  работает только клик и запись нажатий
- Скорость ограничена снизу: Android душит слишком частые жесты

## Отладка

Логи приложения идут в logcat по тегу `AutoClicker`:

```
adb logcat -s AutoClicker
```

Куда что пишется:

| Сообщение | Значит |
|---|---|
| `наблюдатель зарегистрирован, display=0` | Наблюдение за движениями доступно |
| `нажатие X,Y (всего N)` | Нажатие записано |
| `Запись остановлена: N точек` | Запись закрыта, N — количество точек |

Если после переустановки приложение пишет «Служба выключена» — Android
выбивает пакет из списка включённых служб доступности. Включи заново.
